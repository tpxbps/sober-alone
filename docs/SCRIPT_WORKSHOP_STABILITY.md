# 剧本工坊稳定性与交互收敛

实施日期：2026-09-18 起。独立工作树分支 `codex/workshop-stability-cleanup`，基线 `5254dfb781ed9461dd32e88fd39027862b979722`。本次不包含其他工作区的未提交改动；没有修改线上配置、恢复已禁用密钥或部署。

## 根因与推理服务决策

故障不能简单归因为 DeepSeek 不支持结构化输出。已定位到以下实现问题：

1. 大纲调度允许 `ask` 不提供下一段写作任务，Pydantic 却同时要求 `ask` 和 `continue` 的 `next_task` 非空。模型已经返回完整问题，仍会被拒绝；原修复提示没有说明具体字段，反复生成同一类合法问题也无效。现在仅 `continue` 要求下一段任务，推荐选项也允许省略。
2. 新披露规划一次返回整稿所有事实、原文引用和受众，响应会达到输出上限。重发同样的大请求无法修复 `finish_reason=length`。现在先识别角色和开局，再按来源片段分批提取；发现截断继续二分当前批次。
3. 旧线索提示保留 YAML 风格示例，合规提示要求纯文本 PASS/FAIL，与函数输出契约冲突。逐字引文还会因 Markdown 标记、空白或全半角变化误判。现统一函数调用提示、服务端回填来源，并仅容忍格式差异，不接受事实改写。
4. 角色任务内部再次并发生成私人和公开内容，原来只限制外层任务数。四人流程可形成超过网关限额的并发。结构化请求现在共享每工作进程最多四个在途请求的限制，SDK 不再叠加隐式重试。
5. 披露规划中 `actors` 与 `known_by` 两次独立分类容易矛盾，不能把两项模型判断之间的冲突当成可靠的硬校验。现只保留 `known_by` 作为受众依据；保留本人行动的提示、角色材料覆盖检查及对应回归。旧缓存里的额外 `actors` 字段可读取但不再驱动路由。
6. 缺省讨论提示在生成契约中合法，在提交校验中却非法。生成缺省值现在是“请结合已公开的线索自由讨论。”，不会因此要求作者手动补齐。模型给出的无效披露轮次归入作者配置范围，绝不会安排在最终投票之后。

历史对比：本次重构之前，转换任务已经使用 `function_calling`，不是这次才改成函数调用。当前游戏对局的 TokenDance DeepSeek 快速模型反应路径也使用 `function_calling`；其他直连/模型路径依据注册表能力选择输出方式。游戏反应结果短、字段少，不包含整稿事实和长篇角色正文，不能以它的成功证明大体量转换请求没有长度和并发风险。

按照确认后的服务策略，默认保留统一推理入口，没有静默切换或失败后换账号付费。工坊写作、审稿、转换、合规及创作助手固定使用 `deepseek-flash`（当前映射模型），页面不展示具体型号。配置 `SCRIPT_EDITOR_INFERENCE_BACKEND=inherit` 继承全局入口；确需官方直连时可显式设为 `deepseek_official`，仅工坊文本使用 `DEEPSEEK_API_KEY` 与对应 base URL。图片、语音和向量仍沿用原资源入口。旧模型选择配置与客户端参数兼容接收，但不能改变工坊模型。

## 结构化调用与内容边界

所有工坊结构化调用经过同一适配层：指定函数、保留原始响应用于识别停止原因、解析后执行同一套 Pydantic/业务校验。一次调用最多增加一次纠正或传输重试；纠正反馈包含具体字段和错误。认证、配置与推理恢复错误直接返回，截断交给分批器，避免层层重试。只有完整的合法 JSON 文本可以兼容未包裹工具结果的供应商响应，不从普通 prose 猜测或截取对象。

事实批次以最多 24 个片段、约 3000 字为限，单片段最多 600 字，输出预算 8192 tokens。编号和引用由程序校验，成功批次与角色结果持久化到原操作表，刷新、重启、单项失败时可复用。源稿、参数或提示版本变化时缓存失效；生成节点审计记录提示版本、实际模型、停止原因和校验结果。转换阶段的业务错误会将操作标记为失败，不再伪装为完成。

私人材料仍只来源于开局公开或本人已知事实，角色速览和 AI 资料从个人本派生。补强了以下边界：

- “不得提前知道某人到过现场”等作者说明不能当作本人经历；否定句枚举他人秘密行动在个人本、速览、AI 资料输出中会被拒绝并修订。
- “不知道谁才是真凶”属于没有给出答案的正常悬念，不误报为泄密。
- 公开标签不能覆盖明确的有限知情名单，空知情名单也不能自动成为公开材料。
- 提示明确区分物证已经存在与玩家已经发现、公开关系与私人分成/动机，不因为某事实写在开篇或人物总览中就推断全员知情。

这些措施减少已发现的泄底路径，但无法由结构校验证明整篇故事的语义完全正确。模型仍可能误判谁知道什么或生成剧情矛盾，作者审阅与可选质检仍有价值；本次不承诺自动产物无需审稿。

## 交互与状态

大纲只保留当前提问卡的“其他想法或补充说明”输入。选项与补充文本一同提交，文字可以纠正此前设定；如果只修订前文而未回答当前问题，原问题继续保留。移除底部修改输入框、撤销修订、从历史位置修改和可见版本号；数据库内部 revision/checkpoint 继续承担并发保护。

对话记录采用独立的顺序事件，修改有效大纲不会重新排列旧聊天。新记录依次展示正文、问题、作者回答、简短修订反馈与后续内容；旧记录只恢复真实可知的正文快照和已有回答，不虚构精确交错顺序。最终全文可编辑，保存按钮位于预览右侧，直接确认也会提交当前草稿。

每次后台操作只有一个观察器：初次读状态，随后用 SSE 接收增量；正常结束后读取最终状态并停止。等待作者选择或审阅时没有周期轮询。断流或心跳超时才用 5/10/20/30 秒退避补读并重连，恢复后停止轮询。状态、事件序号和操作 ID 共同隔离旧事件；刷新失败的启动/大纲操作会清除已结束的操作 ID，不再锁住输入。

其他界面变化：助手取消多模型选择及品牌说明；创意提示打字间隔缩短至 15 毫秒，仍保留段末 8 秒停留、聚焦停止和减少动态效果支持；各文本审阅页的改进与确认按钮同排；删除“当前显示本次提交内容”横栏但保留提交快照；移除打地鼠组件和样式，长等待提示使用普通静态信息区。

浏览器流程使用离线 API 夹具，真实模型流程调用本地 ASGI API，两类证据各自独立。真实验收覆盖生成后进入游戏，不包括完整玩完一局或线上部署验收。断流、刷新、缓存复用、失败恢复与等待停止请求由自动回归覆盖，不宣称已进行生产服务故障演练。

全部真实测试使用隔离 SQLite、checkpoint 和资源目录，只读取本地私有配置；未使用线上作品作为提交夹具，密钥与生成产物不进入仓库。

复现入口为 `backend/scripts/verify_workshop_live.py`，只显式运行，不进入常规 CI：

```text
python scripts/verify_workshop_live.py --env-file PRIVATE_ENV --output-dir PRIVATE_OUTPUT --backend direct --players 3 --rounds 1 --questions 2
python scripts/verify_workshop_live.py --env-file PRIVATE_ENV --output-dir PRIVATE_OUTPUT --backend tokendance --players 4 --rounds 2 --questions 2 --resources
```

`--conversion-only` 在游戏数据生成后结束，适合结构化矩阵复测；`--retry-failed` 在同一隔离目录恢复失败步骤。TokenDance 全链路必须显式指定 `--resources`，因为清除直连资源密钥不会关闭网关资源。验收脚本遇到结构校验退回时立即失败，不会自动反复提交相同数据。

线上发布仍按既有公开仓库到私有线上版本的流程，在用户验收后进行。此次交付只包含独立分支实现与验证结果。
